# 从原始附件复现论文

本包的数值复现入口是 `reproduce.py`。它使用包内完整源码和附件，在新的工作目录生成一维主解、网格与时间方法对照、二维配对场、参数及后段环境情景，再生成工作簿和七幅数值核查图。`results/` 中的提交结果与 `reference/` 中的论文表格仅用于最后比较，不作为求解初态或计算答案。

## 安装与运行

本轮验收环境为 Python 3.13，依赖版本见 `requirements.txt`。推荐 16 GB 或更多内存；二维对照较耗内存，可用 `--jobs 1` 降低并发。

Windows PowerShell（在解压后的“支撑材料”目录中）：

```powershell
python -m venv ../reproduction-env
../reproduction-env/Scripts/python.exe -X utf8 -m pip install -r requirements.txt
../reproduction-env/Scripts/python.exe -X utf8 reproduce.py --out ../reproduced --jobs 2
```

Linux/macOS：

```sh
python3 -m venv ../reproduction-env
../reproduction-env/bin/python -m pip install -r requirements.txt
../reproduction-env/bin/python reproduce.py --out ../reproduced --jobs 2
```

所有 Excel 文件由 Python 标准库流式导出，并用 openpyxl 重新读取核对，不需要 Node、Codex 或 `@oai/artifact-tool`。旧版分块导出脚本作为历史源码保留，但不被上述完整入口调用。

`--out` 必须位于支撑包之外。已成功完成、源码参数及输出哈希未变的数值任务允许恢复；失败或变化的任务要求新目录，不会把旧文件当作新计算完成。只分阶段运行时可使用 `--stage solve` 和 `--stage postprocess`，默认 `--stage all` 执行完整流程。数值任务全部成功后才执行依赖这些场的后处理。

## 输出与核对

- `reproduced/project/`：包内源码和输入的工作副本，以及本次新计算的未舍入轨迹、完整状态、对照和诊断。
- `reproduced/logs/`：每项实际命令、退出码、耗时、源码集合摘要、输出哈希与完整运行日志。
- `reproduced/comparison.json`：论文六张题设表的逐格核对、关键终点及收缩对照、整根失水表、环境情景表与完整提交数据的数值比较。
- `reproduced/results/result1.xlsx` 至 `result4.xlsx`：从新算数组导出的四问工作簿。其中新生成的 `result2.xlsx` 是完整全过程的工作簿；`result2_前3小时.xlsx` 是单独的小版本。
- `reproduced/results/result2_全程轨迹_206907x21.npz`：全过程每秒、每 0.1 cm 的四位显示数据。
- `reproduced/workbook_verification.json`：重新打开所有导出工作簿，对照新算数组逐格检查。
- `reproduced/figures/`：七幅从新算数据绘制的数值核查图，使用可移植字体。原论文十二幅成品图仍在包内 `figures/`；五幅流程或示意图没有数值求解结果。核查图重现数据内容，不承诺不同操作系统下像素、字体及布局完全相同。

包内 `results/result2.xlsx` 是已提交的前三小时小工作簿，全过程数据在相邻 NPZ。运行上述入口后，完整全过程 Excel 写入新目录；文件名相同但目录和数据范围不同，不能混用。

## 复现的含义

论文六张题设表按原显示精度比较。原始未舍入数、阈值根和已舍入提交数组分别使用明确记录的数值容差，并报告四位显示不一致的单元格数量，不要求不同平台生成的 NPZ/ZIP 哈希相同。

复现证明这些数据确实由给定算法产生，不改变论文模型的适用范围。第四问 51.0921 h 仍为一维条件执行值；粗网格二维终点的结果须如实报告，不能因本次程序运行成功就称为有限圆柱连续全域的严格保证。环境扰动仍是人为设定的条件情景。

实际验收结果由打包程序在计算完成后写入 `复现验收结果.json`；没有该记录或其中失败时，不能宣称本包已完成复现验收。
